# bazi-screenshot-to-report

将用户提供的八字截图，转成可直接喂给报告生成器的数据包（含盘面数据、评分、时间线、策略文案）。

## 适用场景

- 用户只有截图，没有结构化八字数据。
- 用户希望“直接从图生成同款报告”。
- 用户要先抽取数据，再批量复用生成多个报告。

## 与其他 skill 的协作

- 本 skill 负责：**看图抽取 + 结构化 + 衍生评分/文案**。
- 报告落地 HTML 由 `../bazi-report-generator/SKILL.md` 完成。
- 若用户要求“一步到位”，按本 skill 完成数据包后，直接进入报告 skill 流程。

## 输入要求

最少输入：

1. 至少 1 张清晰八字截图（包含四柱、大运、流年区域）。
2. 用户确认报告名称（可默认“八字全周期大运趋势看板报告”）。

建议输入（可选）：

- 用户对语气偏好（保守/直接/鼓励型）。
- 是否保留原图中的专业字段（如神煞、纳音）在正文展示。

## 输出目标

输出一个“报告就绪数据包”（report-ready payload），包含：

- 个人与时间信息：姓名、阴阳历、年龄、当前大运、当前流年。
- 四柱核心盘面：主星、天干、地支、藏干、十神。
- 大运序列与流年序列。
- 大运阶段分与当前大运内流年分。
- 时间线主题/评论/策略文案。
- 桃花窗口与行动策略文案。
- 不确定字段清单（`needsConfirm`）。

## 执行流程（严格顺序）

1. **图片可读性检查**
   - 若关键信息区域模糊、截断、遮挡，先标记缺失字段，不臆造。
2. **分区抽取（按版式）**
   - 顶部身份区：姓名、阴历、阳历、造（乾/坤）、当前年龄。
   - 左侧命盘区：流年/大运/年柱/月柱/日柱/时柱的主星、天干、地支、藏干。
   - 右侧运势区：起运、交运、大运行、流年行（必要时含流月用于辅助判断）。
3. **字段标准化**
   - 统一十神简称：比/劫/食/伤/财/才/官/杀/印/枭。
   - 统一元素标签：木/火/土/金/水。
   - 年龄段统一成 `N-M岁` 文本格式。
4. **衍生计算**
   - 从大运起始年推导各阶段年龄段。
   - 锁定“当前大运”和“当前流年”对应索引。
5. **评分生成（当截图未给出评分时）**
   - 先判定日主强弱与喜忌大方向。
   - 对每步大运与流年做相对评分（0-100），保持同一份报告内部排序一致。
   - 输出评分等级：`red/gold/green/sauce/gray`。
6. **文案生成**
   - 按“现象 + 风险 + 建议动作”三段式写法。
   - 禁用绝对化预测措辞（如“必然”“注定”）。
7. **生成结构化数据包**
   - 以 JSON 或 YAML 给出。
   - 附 `needsConfirm` 与 `assumptions`。

## 评分规则（缺省方案）

当用户未提供任何分数时，使用以下统一方法：

1. 基准分：`60`
2. 大运评分调整：
   - 命局喜用元素明显增强：`+8 ~ +18`
   - 忌神增强或冲刑害密集：`-8 ~ -18`
   - 结构重组但可控：`-5 ~ +5`
3. 流年评分调整（在所属大运基础上浮动）：
   - 强助喜用：`+6 ~ +14`
   - 引动冲突/反复：`-6 ~ -14`
4. 限幅：`[35, 92]`
5. 颜色映射：
   - `>= 86`: `red`
   - `76-85`: `gold`
   - `58-75`: `green`
   - `46-57`: `sauce`
   - `<= 45`: `gray`

说明：分数用于“阶段趋势可视化”，不是概率学结论。

## 不确定性处理（必须执行）

- 截图看不清或被遮挡字段：填 `null`，并写入 `needsConfirm`。
- 不可确认的信息禁止脑补（尤其出生时分、干支、起运规则）。
- 对推断项写入 `assumptions`，便于用户核对。

## 页面口径对齐（必须匹配现版报告）

- 顶部必须包含免责声明（AI生成、非预测、命运在己）。
- 模块命名使用：
  - `当前{大运名}中流年运势`
  - `桃花 / 恋爱高概率年份`
  - `行动策略`
- 当前大运流年表数据需直接可用于 3 列结构：
  - `势 / 评分`
  - `年份 / 流年`
  - `策略定位`

## 质量校验清单（交付前）

1. 是否覆盖报告全部必需字段。
2. 当前年龄、当前大运、当前流年是否一致。
3. 大运与流年年份是否连续、无错位。
4. 分数与等级映射是否一致。
5. 所有不确定字段是否进入 `needsConfirm`。

## 一步到位输出建议

当用户说“直接给我报告”时，按以下顺序输出：

1. 先给 `report-ready payload`。
2. 再调用/衔接 `bazi-report-generator` 产出最终 HTML。
3. 最后附核对项（仅列 `needsConfirm`）。
